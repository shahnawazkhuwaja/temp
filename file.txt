================================================================================
SECTION 1 — DATA MODELS (THEORY)
================================================================================

A data model defines how data is structured, stored, and manipulated.

Types of Data Models:
  - Hierarchical   : Tree structure, parent-child relationships
  - Network        : Graph structure, many-to-many via pointers
  - Relational      : Tables with rows/columns, SQL-based (Oracle, MySQL)
  - Document/NoSQL  : JSON-like documents, e.g. MongoDB, no fixed schema
  - ER Model        : Conceptual model using entities and relationships

--------------------------------------------------------------------------------
RDBMS vs MongoDB Terminology — MEMORIZE THIS:
--------------------------------------------------------------------------------

  RDBMS              |  MongoDB
  -------------------|---------------------------
  Database           |  Database
  Table              |  Collection
  Row / Tuple        |  Document
  Column             |  Field
  Table Join         |  Embedded Document
  Primary Key        |  _id (auto-provided)
  mysqld / Oracle    |  mongod (server)
  mysql / sqlplus    |  mongo / mongosh (shell)

SECTION 2 — Q1: ER MODEL + RELATIONAL SCHEMA (DDL)
================================================================================

HOW TO APPROACH ANY SCENARIO:
  Step 1 — Read paragraph, identify ENTITIES (nouns)
  Step 2 — Identify ATTRIBUTES (properties of each entity)
  Step 3 — Identify RELATIONSHIPS between entities
  Step 4 — Determine cardinality: 1:1, 1:N, or M:N
  Step 5 — Write CREATE TABLE with PKs, FKs, constraints

CARDINALITY RULES:
  1:N  → FK goes in the MANY side table
  M:N  → Create a JUNCTION/BRIDGE table with composite PK
  1:1  → FK goes in the weaker entity

TODAY'S EXAM Q1 SOLUTION — Smart Agriculture Monitoring System
--------------------------------------------------------------------------------

Entities: FARMING_ZONE, FARMER, CROP, EQUIPMENT, HARVEST, DISTRIBUTION_CENTER
M:N Relationships: Farmer-Zone, Crop-Zone, Zone-DistributionCenter

-- Step 1: FARMING_ZONE
CREATE TABLE FARMING_ZONE (
    zone_code       VARCHAR2(10)    PRIMARY KEY,
    zone_name       VARCHAR2(50)    NOT NULL,
    climate_type    VARCHAR2(30),
    soil_quality    VARCHAR2(20),
    total_area      NUMBER(10,2)
);

-- Step 2: FARMER
CREATE TABLE FARMER (
    farmer_id       NUMBER          PRIMARY KEY,
    farmer_name     VARCHAR2(50)    NOT NULL,
    experience      NUMBER,
    contact         VARCHAR2(15)
);

-- Step 3: FARMER_ZONE (M:N junction table)
CREATE TABLE FARMER_ZONE (
    farmer_id       NUMBER,
    zone_code       VARCHAR2(10),
    start_date      DATE,
    PRIMARY KEY (farmer_id, zone_code),
    FOREIGN KEY (farmer_id)  REFERENCES FARMER(farmer_id),
    FOREIGN KEY (zone_code)  REFERENCES FARMING_ZONE(zone_code)
);

-- Step 4: CROP
CREATE TABLE CROP (
    crop_id         NUMBER          PRIMARY KEY,
    crop_name       VARCHAR2(50)    NOT NULL,
    season          VARCHAR2(20),
    growth_duration NUMBER
);

-- Step 5: ZONE_CROP (M:N junction table)
CREATE TABLE ZONE_CROP (
    zone_code       VARCHAR2(10),
    crop_id         NUMBER,
    PRIMARY KEY (zone_code, crop_id),
    FOREIGN KEY (zone_code) REFERENCES FARMING_ZONE(zone_code),
    FOREIGN KEY (crop_id)   REFERENCES CROP(crop_id)
);

-- Step 6: EQUIPMENT (belongs to ONE zone — 1:N)
CREATE TABLE EQUIPMENT (
    equipment_id    NUMBER          PRIMARY KEY,
    eq_type         VARCHAR2(30),
    purpose         VARCHAR2(50),
    status          VARCHAR2(20),
    zone_code       VARCHAR2(10),
    FOREIGN KEY (zone_code) REFERENCES FARMING_ZONE(zone_code)
);

-- Step 7: HARVEST
CREATE TABLE HARVEST (
    harvest_id      NUMBER          PRIMARY KEY,
    harvest_date    DATE,
    quantity        NUMBER(10,2),
    quality_grade   VARCHAR2(5),
    crop_id         NUMBER,
    zone_code       VARCHAR2(10),
    FOREIGN KEY (crop_id)   REFERENCES CROP(crop_id),
    FOREIGN KEY (zone_code) REFERENCES FARMING_ZONE(zone_code)
);

-- Step 8: DISTRIBUTION_CENTER
CREATE TABLE DISTRIBUTION_CENTER (
    center_id       NUMBER          PRIMARY KEY,
    location        VARCHAR2(50),
    capacity        NUMBER,
    manager         VARCHAR2(50)
);

-- Step 9: ZONE_DISTRIBUTION (M:N junction table)
CREATE TABLE ZONE_DISTRIBUTION (
    zone_code       VARCHAR2(10),
    center_id       NUMBER,
    PRIMARY KEY (zone_code, center_id),
    FOREIGN KEY (zone_code)  REFERENCES FARMING_ZONE(zone_code),
    FOREIGN KEY (center_id)  REFERENCES DISTRIBUTION_CENTER(center_id)
);

KEY RULES TO REMEMBER:
  - 1:N  → FK goes in the MANY side (EQUIPMENT has zone_code FK)
  - M:N  → Always create junction table with composite PK
  - Always use NOT NULL on name/ID columns
  - Junction table PK = combination of both FKs

SECTION 3 — Q2: MONGODB
================================================================================

SENTENCE TO COMMAND MAPPING — READ THE SCENARIO AND MATCH:

  "checks available databases"                   -->  show dbs
  "switches to a working database"               -->  use database_name
  "collection is created"                        -->  db.createCollection("name")
  "stores a single record"                       -->  db.col.insertOne({...})
  "stores multiple records"                      -->  db.col.insertMany([{...},{...}])
  "displays all data to verify"                  -->  db.col.find()
  "retrieves in descending order"                -->  db.col.find({}).sort({field: -1})
  "retrieves in ascending order"                 -->  db.col.find({}).sort({field: 1})
  "filters records NOT belonging to X"           -->  db.col.find({field: {$ne: "X"}})
  "updated / reassigned"                         -->  db.col.updateOne({filter},{$set:{...}})
  "rechecks updated records"                     -->  db.col.find({status: "treated"})
  "display only selected fields"                 -->  db.col.find({},{field:1,_id:0})
  "grouping and calculating average"             -->  db.col.aggregate([{$group:{...}}])
  "drop collection"                              -->  db.col.drop()
  "drop database"                                -->  db.dropDatabase()

ALL MONGODB OPERATORS — QUICK REFERENCE
--------------------------------------------------------------------------------

  $gt       Greater than           {salary: {$gt: 5000}}
  $gte      Greater than or equal  {age: {$gte: 18}}
  $lt       Less than              {score: {$lt: 90}}
  $lte      Less than or equal     {score: {$lte: 90}}
  $ne       Not equal              {zone: {$ne: "South"}}
  $and      AND condition          {$and: [{f1:v1},{f2:v2}]}
  $or       OR condition           {$or: [{f1:v1},{f2:v2}]}
  $set      Set field value        {$set: {field: value}}
  $inc      Increment value        {$inc: {score: 5}}
  $avg      Average (aggregate)    {$avg: "$field"}
  $sum      Sum/Count (aggregate)  {$sum: 1}
  $group    Group documents        {$group: {_id: "$field"}}
  $regex    Pattern match          {name: {$regex: "^A", $options: "i"}}

-- Q3.1: Subquery — employees earning more than max salary in OTHER departments
--        Also display job title and department location

SELECT e.EMPLOYEE_ID, e.FIRST_NAME, e.LAST_NAME,
       j.JOB_TITLE, l.CITY
FROM employees e
JOIN jobs j        ON e.JOB_ID = j.JOB_ID
JOIN departments d ON e.DEPARTMENT_ID = d.DEPARTMENT_ID
JOIN locations l   ON d.LOCATION_ID = l.LOCATION_ID
WHERE e.SALARY > (
    SELECT MAX(e2.SALARY)
    FROM employees e2
    WHERE e2.DEPARTMENT_ID != e.DEPARTMENT_ID
);

-- Q3.2: JOIN — employees with active job + dept in approved region

SELECT e.EMPLOYEE_ID, e.FIRST_NAME, e.LAST_NAME,
       j.JOB_TITLE, d.DEPARTMENT_NAME, l.CITY, c.COUNTRY_NAME
FROM employees e
JOIN jobs j        ON e.JOB_ID = j.JOB_ID
JOIN departments d ON e.DEPARTMENT_ID = d.DEPARTMENT_ID
JOIN locations l   ON d.LOCATION_ID = l.LOCATION_ID
JOIN countries c   ON l.COUNTRY_ID = c.COUNTRY_ID
WHERE e.JOB_ID IS NOT NULL
  AND c.REGION_ID IN (1, 2);

-- Q3.3: Correlated Subquery — salary > at least one in same dept,
--        but < max salary in same dept

SELECT e.EMPLOYEE_ID, e.FIRST_NAME, e.SALARY, e.DEPARTMENT_ID
FROM employees e
WHERE e.SALARY > (
    SELECT MIN(e2.SALARY)
    FROM employees e2
    WHERE e2.DEPARTMENT_ID = e.DEPARTMENT_ID   -- correlated (references outer)
      AND e2.EMPLOYEE_ID  != e.EMPLOYEE_ID
)
AND e.SALARY < (
    SELECT MAX(e3.SALARY)
    FROM employees e3
    WHERE e3.DEPARTMENT_ID = e.DEPARTMENT_ID   -- correlated (references outer)
);

-- Q3.4: Salary within range (above min, below max of dept) + dept name + region

SELECT e.EMPLOYEE_ID, e.FIRST_NAME, e.SALARY,
       d.DEPARTMENT_NAME, l.CITY
FROM employees e
JOIN departments d ON e.DEPARTMENT_ID = d.DEPARTMENT_ID
JOIN locations l   ON d.LOCATION_ID = l.LOCATION_ID
WHERE e.SALARY > (
    SELECT MIN(e2.SALARY)
    FROM employees e2
    WHERE e2.DEPARTMENT_ID = e.DEPARTMENT_ID
)
AND e.SALARY < (
    SELECT MAX(e3.SALARY)
    FROM employees e3
    WHERE e3.DEPARTMENT_ID = e.DEPARTMENT_ID
);

-- Q3.5: Trigger — Employee Transfer Validation
--        Validates new dept, prevents invalid transfers, logs to history

-- Step 1: Create history table
CREATE TABLE transfer_history (
    transfer_id   NUMBER         PRIMARY KEY,
    employee_id   NUMBER,
    old_dept_id   NUMBER,
    new_dept_id   NUMBER,
    transfer_date DATE
);

-- Step 2: Create sequence for auto-increment ID
CREATE SEQUENCE transfer_seq START WITH 1 INCREMENT BY 1;

-- Step 3: Trigger
CREATE OR REPLACE TRIGGER trg_employee_transfer
BEFORE UPDATE OF DEPARTMENT_ID ON employees
FOR EACH ROW
DECLARE
    v_dept_count  NUMBER;
BEGIN
    -- Check if new department is valid
    SELECT COUNT(*) INTO v_dept_count
    FROM departments
    WHERE DEPARTMENT_ID = :NEW.DEPARTMENT_ID;

    IF v_dept_count = 0 THEN
        RAISE_APPLICATION_ERROR(-20002, 'Invalid or inactive department code');
    END IF;

    -- Record the transfer in history
    INSERT INTO transfer_history VALUES (
        transfer_seq.NEXTVAL,
        :OLD.EMPLOYEE_ID,
        :OLD.DEPARTMENT_ID,
        :NEW.DEPARTMENT_ID,
        SYSDATE
    );
END;

TODAY'S EXAM B1 — Total and average salary per department
--------------------------------------------------------------------------------

SET SERVEROUTPUT ON;
CREATE OR REPLACE PROCEDURE dept_salary_summary
IS
BEGIN
    FOR rec IN (
        SELECT d.DEPARTMENT_ID,
               d.DEPARTMENT_NAME,
               SUM(e.SALARY)           AS total_sal,
               ROUND(AVG(e.SALARY), 2) AS avg_sal
        FROM employees e
        JOIN departments d ON e.DEPARTMENT_ID = d.DEPARTMENT_ID
        GROUP BY d.DEPARTMENT_ID, d.DEPARTMENT_NAME
    )
    LOOP
        DBMS_OUTPUT.PUT_LINE(
            'Dept ID: '   || rec.DEPARTMENT_ID   ||
            ' | Name: '   || rec.DEPARTMENT_NAME ||
            ' | Total: '  || rec.total_sal       ||
            ' | Avg: '    || rec.avg_sal
        );
    END LOOP;
END;
/

CREATE OR REPLACE PROCEDURE remove_duplicate_employees
IS
BEGIN
    -- Keep only the row with the smallest EMPLOYEE_ID for each name pair
    DELETE FROM employees
    WHERE EMPLOYEE_ID NOT IN (
        SELECT MIN(EMPLOYEE_ID)
        FROM employees
        GROUP BY FIRST_NAME, LAST_NAME
    );

    DBMS_OUTPUT.PUT_LINE('Duplicate rows removed: ' || SQL%ROWCOUNT);
    COMMIT;
END;

--------------------------------------------------------------------------------
TODAY'S EXAM A1 — Admit patient + log entry together (both or neither)

BEGIN

    WHERE status = 'admitted';

    SAVEPOINT phase1_done;  -- CHECKPOINT created here
    DBMS_OUTPUT.PUT_LINE('Phase 1 complete. Checkpoint set.');

    -- ===== PHASE 2 =====
    UPDATE Patients
    SET bill_amount = bill_amount * 1.1
    WHERE status = 'in treatment';

    DELETE FROM Treatment_Log
    WHERE log_date < SYSDATE - 30;

    COMMIT;  -- Both phases saved if no error
    DBMS_OUTPUT.PUT_LINE('All phases committed successfully.');
EXCEPTION
    WHEN OTHERS THEN
        ROLLBACK TO phase1_done;  -- Only undo PHASE 2
        COMMIT;                   -- Keep PHASE 1
        DBMS_OUTPUT.PUT_LINE('Phase 2 failed. Phase 1 kept intact.');
END;
/

-- OUT Parameter — procedure returns a value to the caller
CREATE OR REPLACE PROCEDURE Get_Salary (
    e_id   IN  NUMBER,
    e_sal  OUT NUMBER
)
IS
BEGIN
    SELECT SALARY INTO e_sal
    FROM employees
    WHERE EMPLOYEE_ID = e_id;
END;
/

-- Execution — need a variable to receive OUT value
DECLARE
    salary NUMBER;
BEGIN
    Get_Salary(100, salary);
    DBMS_OUTPUT.PUT_LINE('Salary: ' || salary);
END;
/

-- IN OUT Parameter — pass value in, get modified value back
CREATE OR REPLACE PROCEDURE Update_Value (
    num IN OUT NUMBER
)
IS
BEGIN
    num := num + 10;
END;
/

-- Execution
DECLARE
    val NUMBER := 50;
BEGIN
    Update_Value(val);
    DBMS_OUTPUT.PUT_LINE('Updated Value: ' || val);  -- prints 60
END;
/

-- BEFORE INSERT trigger

-- Combined INSERT/UPDATE/DELETE trigger
CREATE OR REPLACE TRIGGER tr_employees
BEFORE INSERT OR UPDATE OR DELETE ON employees
FOR EACH ROW ENABLE
DECLARE
    v_user VARCHAR2(30);
BEGIN
    SELECT user INTO v_user FROM dual;
    IF INSERTING THEN
        DBMS_OUTPUT.PUT_LINE('Inserted by ' || v_user);
    ELSIF UPDATING THEN
        DBMS_OUTPUT.PUT_LINE('Updated by ' || v_user);
    ELSIF DELETING THEN
        DBMS_OUTPUT.PUT_LINE('Deleted by ' || v_user);
    END IF;
END;
/

-- Table Auditing Trigger (stores :NEW and :OLD values)
CREATE TABLE emp_audit (
    new_sal    NUMBER,
    old_sal    NUMBER,
    user_name  VARCHAR2(30),
    entry_date VARCHAR2(30),
    operation  VARCHAR2(20)
);

CREATE OR REPLACE TRIGGER emp_audit_tr
BEFORE INSERT OR UPDATE OR DELETE ON employees
FOR EACH ROW ENABLE
DECLARE
    v_user VARCHAR2(30);
    v_date VARCHAR2(30);
BEGIN
    SELECT user, TO_CHAR(SYSDATE, 'DD/MON/YYYY HH24:MI:SS')
    INTO v_user, v_date FROM dual;

    IF INSERTING THEN
        INSERT INTO emp_audit VALUES
            (:NEW.SALARY, NULL, v_user, v_date, 'INSERT');
    ELSIF DELETING THEN
        INSERT INTO emp_audit VALUES
            (NULL, :OLD.SALARY, v_user, v_date, 'DELETE');
    ELSIF UPDATING THEN
        INSERT INTO emp_audit VALUES
            (:NEW.SALARY, :OLD.SALARY, v_user, v_date, 'UPDATE');
    END IF;
END;
/

-- Synchronized Backup Trigger
CREATE TABLE employees_backup AS SELECT * FROM employees WHERE 1=2;

CREATE OR REPLACE TRIGGER emp_backup_tr
BEFORE INSERT OR UPDATE OR DELETE ON employees
FOR EACH ROW ENABLE
BEGIN
    IF INSERTING THEN
        INSERT INTO employees_backup
        VALUES (:NEW.EMPLOYEE_ID, :NEW.FIRST_NAME, :NEW.LAST_NAME,
                :NEW.EMAIL, :NEW.PHONE_NUMBER, :NEW.HIRE_DATE,
                :NEW.JOB_ID, :NEW.SALARY, :NEW.COMMISSION_PCT,
                :NEW.MANAGER_ID, :NEW.DEPARTMENT_ID);
    ELSIF DELETING THEN
        DELETE FROM employees_backup
        WHERE EMPLOYEE_ID = :OLD.EMPLOYEE_ID;
    ELSIF UPDATING THEN
        UPDATE employees_backup
        SET SALARY = :NEW.SALARY
        WHERE EMPLOYEE_ID = :OLD.EMPLOYEE_ID;
    END IF;
END;
/

-- INSTEAD OF INSERT Trigger (for non-updatable views)
CREATE TABLE trainer (full_name VARCHAR2(20));
CREATE TABLE subject (subject_name VARCHAR2(15));

CREATE VIEW db_lab_view AS
    SELECT full_name, subject_name FROM trainer, subject;

CREATE OR REPLACE TRIGGER tr_io_insert
INSTEAD OF INSERT ON db_lab_view
FOR EACH ROW
BEGIN
    INSERT INTO trainer (full_name)      VALUES (:NEW.full_name);
    INSERT INTO subject (subject_name)   VALUES (:NEW.subject_name);
END;
/

-- INSTEAD OF UPDATE Trigger
CREATE OR REPLACE TRIGGER tr_io_update
INSTEAD OF UPDATE ON db_lab_view
FOR EACH ROW
BEGIN
    UPDATE trainer SET full_name     = :NEW.full_name
    WHERE full_name = :OLD.full_name;

    UPDATE subject SET subject_name  = :NEW.subject_name
    WHERE subject_name = :OLD.subject_name;
END;
/

-- INSTEAD OF DELETE Trigger
CREATE OR REPLACE TRIGGER tr_io_delete
INSTEAD OF DELETE ON db_lab_view
FOR EACH ROW
BEGIN
    DELETE FROM trainer WHERE full_name    = :OLD.full_name;
    DELETE FROM subject WHERE subject_name = :OLD.subject_name;
END;
/

================================================================================
SECTION 6 — CRITICAL CHEAT SHEET
================================================================================

5 LINES YOU MUST MEMORIZE:
  SQL%ROWCOUNT                              -- rows affected by last DML
  TO_CHAR(HIRE_DATE, 'DY')                  -- SAT, SUN, MON etc.
  TO_CHAR(SYSDATE, 'DD/MON/YYYY HH24:MI:SS')-- formatted date string
  RAISE_APPLICATION_ERROR(-20001, 'msg')    -- throw custom error
  :OLD.col / :NEW.col                       -- before/after values in triggers
  FOR EACH ROW                              -- required for :OLD/:NEW
  SQLERRM                                   -- error message in EXCEPTION block

TRANSACTION KEYWORDS:
  COMMIT                  -- permanently save all changes
  ROLLBACK                -- undo ALL changes to last commit
  SAVEPOINT name          -- create a named checkpoint
  ROLLBACK TO name        -- undo only changes AFTER savepoint
  WHEN OTHERS THEN        -- catch any exception
  SQL%ROWCOUNT            -- number of rows affected

TRIGGER TYPES SUMMARY:
  BEFORE INSERT OR UPDATE OR DELETE ON table FOR EACH ROW  -- DML trigger
  AFTER UPDATE OF column ON table FOR EACH ROW             -- column-specific
  AFTER DDL ON SCHEMA                                      -- schema audit
  AFTER DDL ON DATABASE                                    -- database audit (DBA)
  AFTER LOGON ON SCHEMA                                    -- login trigger
  BEFORE LOGOFF ON SCHEMA                                  -- logout trigger
  AFTER STARTUP ON DATABASE                                -- startup (DBA)
  BEFORE SHUTDOWN ON DATABASE                              -- shutdown (DBA)
  INSTEAD OF INSERT ON view_name FOR EACH ROW              -- instead-of (views)

PARAMETER MODES IN PROCEDURES:
  IN      -- caller passes value IN, procedure cannot modify it
  OUT     -- procedure sends value OUT to caller
  IN OUT  -- value passed in AND returned modified

PSEUDO RECORDS IN TRIGGERS:
  Operation  | :NEW         | :OLD
  -----------|--------------|-------------
  INSERT     | new values   | NULL
  UPDATE     | new values   | old values
  DELETE     | NULL         | old values

MONGODB KEY RULES:
  - use dbname      -- does NOT create DB until data is inserted
  - sort({f: -1})   -- descending
  - sort({f:  1})   -- ascending
  - {f: 1, _id: 0}  -- projection: include f, exclude _id
  - Cannot mix include (1) and exclude (0) in projection
    EXCEPT for _id which can always be set to 0

DDL RULES FOR Q1:
  - 1:N   --> FK in the MANY side
  - M:N   --> junction table with composite PK
  - NOT NULL on all name/important columns
  - REFERENCES keyword for foreign keys
  - Submit ER diagram AND DDL separately
